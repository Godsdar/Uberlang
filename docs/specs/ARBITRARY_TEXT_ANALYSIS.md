# Анализ произвольного текста: ТЗ и этапы

Дата: 2026-10-19. База: опубликованный main `87b10bd`. Статус: этап 1 в отдельной
ветке; публикация и интеграция с Anki выполняются последовательно родителем.

## Проверяемая проблема

Live English уже вычисляется spaCy для новых предложений; offline содержит лишь
три точных подготовленных примера. Браузер безусловно объявляет любой текст
английским, а worker не получает язык: `Мама читает книгу.` получает ложный
Live grammar. Объяснение предложения — правила над зависимостями, словарь не
выбирает значение по контексту, переводы в notebook подготовлены. Редактор на
6000 единиц UTF-16 не означает анализ документа целиком.

## Этап 1 — контракт и честный интерфейс

1. Явно объявленный язык проходит browser → Node → Python → provenance. После
   редактирования/вставки своего текста язык нужно выбрать; заготовленные English
   примеры объявляют свой язык. Только `en` имеет установленную грамматическую
   модель. Остальные коды дают `UNSUPPORTED_LANGUAGE` до вызова модели.
2. Проверка письма отклоняет нелатинские буквы и смешанное письмо даже при `en`.
   Допущены basic Latin, Latin-1/Extended-A/B/Additional; более редкие
   Latin-блоки также отклоняются. Это консервативный фильтр, а не language detection. Он также отклоняет English
   с цитатами/именами другим письмом. Французский/испанский на латинице распознать
   таким фильтром нельзя: ответственность за выбранный язык явно показана.
3. Общие browser/Node лимиты: документ 6000, отправляемое предложение 500 единиц
   UTF-16, 50 слов; Unicode combining marks входят в слово. Python повторяет
   контракт и проверяет предложение моделью. Никакого обрезания или нормализации
   исходника; диапазоны UTF-16 [start,end), повторения раздельны. Отсутствие букв,
   некорректный Unicode и неверные диапазоны не дают грамматику.
4. Live grammar означает вычисленные предсказания конкретной English-модели,
   не подтверждённый смысл. Структурное чтение обозначено как rule-based,
   словарные значения — альтернативы, подготовленный перевод — prepared,
   отсутствующий перевод/значение — unavailable. Новые примеры содержат только
   текст, никаких ответов/переводов. Их загрузка не отправляет запрос.
5. Редактирование, смена языка и контекста отменяют запросы и инвалидируют
   результаты. Неподдерживаемый язык не получает даже English fixture grammar.
   Ошибка live-запроса не маскируется подготовленным ответом. Offline fallback
   остаётся только для точного подготовленного текста с явной маркировкой.
6. Capabilities сообщает configured engine, поддерживаемые языки, модель,
   пределы, доступные слои и отсутствие autodetect; configured не равно healthy.
   Публичные маршруты, ключи, права, сеть и провайдеры не расширяются.

## Приёмка

- `Мама читает книгу.` с `ru` и с ошибочно выбранным `en` не вызывает parser и не
  отображает POS/Live grammar; такое же правило действует на приватном worker.
- Неизвестное новое English предложение действительно проходит установленную
  модель. Выдуманные публичные примеры используются для QA, личные тексты — нет.
- Spanish/French с правильно объявленным языком отклоняется; латинский текст с
  ошибочно объявленным `en` остаётся известным ограничением, не обещанием LID.
- Корпус покрывает отрицание/вопрос/пассив/неоднозначность, повторы, emoji,
  диакритику NFC/NFD, unsupported/mixed scripts, границы 50/51 и 500/501,
  несколько предложений, offline/unavailable и stale responses.
- Node/domain/API тесты, Python с реальной pinned-моделью, typecheck, четыре
  сборки + gateway, smoke; реальный UI desktop/390px, три темы, клавиатура,
  смена языка/текста, отсутствие автоматической отправки, ошибочные входы.
- Отдельное ревью. Малые коммиты, без push/deploy до передачи родителю.

## Следующие этапы — требуют выбора и ресурсов

**Многоязычие.** Реестр адаптеров по языку и версии: installed model, native label
scheme, tokenizer, morphology, sentence segmentation, licence, лимиты, профиль
качества. Установка отдельной модели не равна качественному контекстному разбору.
Сначала выбрать 1–2 языка и корпуса с компетентным языковым ревью. Проверить
размер артефакта, память, cold start и p95 на текущем бесплатном hosting; решение
о новых ресурсах принимает пользователь. Никогда не fallback к English для
неподдерживаемого языка. `xx`/blank tokenizer не заменяет обученный dependency
parser. Смешанные языки: явный отказ до отдельного измеренного дизайна.

**Документ.** Локально выделять предложения с неизменными absolute offsets;
явно показывать объём отправки. Пакетный анализ только после решения о лимитах,
CPU/памяти/отмене и частичных результатах. Одно неудачное предложение не должно
обнулять остальные; статус каждого слоя и предложения независим.

**Контекст.** Разделить predicted syntax, rule-derived reading, dictionary senses,
chosen sense и translation. Можно показывать кандидаты значения и дать человеку
явный выбор с сохранением источника/ревизии. POS — лишь подсказка, не доказательство
значения; фразовые глаголы, polysemy, coreference, negation scope, idioms и irony
нуждаются в отдельном корпусе. Не называть subject/object объяснение пониманием.
Локальную semantic/WSD/translation модель выбирать только после сравнительного
теста, лицензии, памяти, latency и согласования. Внешняя LLM/API/новая передача
личного контекста требует прямого решения пользователя; в этом этапе её нет.

**Оценка.** Раздельно измерять корректность языка/отказов, exact slices/tree
integrity, POS/morph/dependency accuracy, sentence boundary accuracy, sense
selection accuracy/abstention и p50/p95. Проверки целостности дерева не являются
сертификатом лингвистической точности. Тестовый корпус синтетический, без личных
данных; для accuracy нужны ручные gold annotations и held-out набор каждого языка.

## Первичные источники (проверены 2026-10-19)

- https://spacy.io/models/en — English pipeline/model card; trained domain and
  separate components; pinned project remains 3.8.7 / en_core_web_sm 3.8.0.
- https://spacy.io/usage/models — language data versus trained pipelines,
  installation/versioning; blank/xx support is not universal grammar.
- https://spacy.io/usage/linguistic-features — statistical POS/dependency parsing,
  sentence boundaries and morphology; predictions are not contextual semantics.
