## Что есть сейчас

Общее ядро `src/core/` используется Electron, веб-приложением и Chrome MV3. UI написан на React/MUI, дерево — React SVG с `d3-hierarchy` и `motion`. Языки текущего публичного контракта: EN, RU, ES, FR. Словарь — English Wiktionary; переводческие провайдеры подключаются через `providers.ts`. Есть компоненты локальной коллекции и шаринга.

Исходный аудит 11 октября зафиксировал следующие ограничения (изменения 13 октября — в ревью):

- `analyze.ts` берёт первые восемь уникальных слов. Повторения, позиции и пунктуация не сохраняются. Это словарный обзор, а не разбор синтаксиса предложения.
- Часть речи и первый перевод словарной статьи не обязательно соответствуют употреблению в предложении. Переводы сейчас не привязаны к выбранному значению.
- Этимология хранится линейными цепочками. `buildEtymologyTree` соединяет две цепочки — слово и перевод; боковые родственники требуют новой модели данных.
- Парсер ветвящегося `ety-tree` складывает узлы в плоский список. Соседство в таком списке нельзя считать доказательством прямого происхождения.
- Анализ и рендер используют разные правила поиска общего предка. Их нужно согласовать; одна доступная цепочка также не должна считаться общим корнем двух слов.
- В сборке дерева теряется поле типа связи. Заимствование и наследование сейчас не различаются в геометрии.
- Ошибку загрузки, неполноту парсинга и отсутствие словарных данных нужно показывать отдельными состояниями.

Локальная копия на коммите `29635e9` не имеет команды `npm test`; прочитанный GitHub `main` уже содержит `node --test src/core/etymologyTree.test.ts`. GitHub AGENTS всё ещё сообщает об отсутствии раннера. Перед кодированием выбрать актуальный базовый коммит и согласовать инструкции с фактическими тестами. Не перезаписывать локальную копию автоматически.

Старый `docs/ETYMOLOGY_TREE.md` ограничивает дерево двумя листьями; новый запрос расширяет объём. ADR-006 задаёт веб первым, локальное хранение и отсутствие ежедневного пазла на старте. Некоторые статусы DESIGN/PIPELINE устарели относительно README. Скриншот в README показывает старый UI и не служит образцом текущего рендера.

## Первый законченный сценарий

1. Пользователь выбирает язык и вводит одно предложение. В первом пилоте предлагаемый предел — 50 токенов или 500 символов; превышение объясняется, текст не обрезается молча.
2. Явное действие **Analyze sentence** запускает выбранный грамматический движок. Ввод не должен автоматически отправляться новому облачному сервису во время набора.
3. Первый результат — понятное объяснение смысла и структуры на английском. Перевод раскрывается по желанию, отдельно от объяснения и грамматики. Ошибка переводчика не скрывает доступный грамматический результат.
4. В исходном тексте сохраняются все слова и пунктуация. Клик по слову выделяет его в предложении и показывает карточку.
5. Карточка содержит исходную форму, лемму, часть речи в контексте, доступные грамматические признаки, главное слово и тип зависимости. Краткое объяснение термина доступно по запросу.
6. Вид **Sentence structure** показывает зависимости слов. Переключение на **Word origins** открывает этимологию выбранной леммы и подходящего словарного значения.
7. В этимологическом дереве видна основная линия происхождения и умеренное число подтверждённых родственников. Другие ветви раскрываются по действию пользователя.
8. Пользователь сохраняет интересное открытие локально или экспортирует отчёт с контекстом, объяснением, грамматикой и деревом с источниками. Отправка отчёта другому человеку всегда ручная.

На первом экране не нужно одновременно показывать подробный синтаксис, все словарные значения и всю этимологическую семью. Полный разбор должен быть доступен без перегрузки начального вида.

### Короткие фразы и длинный текст

Главный сценарий — небольшая фраза, которой пользователь хочет разобраться. Для длинного текста приложение становится пространством чтения: разбор запускается для выбранного слова или выражения, а не сразу для каждого слова во всём документе. Синтаксис требует контекста, поэтому движку передаётся выбранный фрагмент вместе с содержащим его предложением; границы отправляемого контекста видны до облачного запроса. Этимология строится для выбранной леммы и значения.

Сохранять исходный документ и диапазоны каждого выбранного вхождения. Повтор одного слова в другом месте — другая заметка. Выделение выражения может связывать несколько токенов, но выражению не приписывается единая история слова. Для идиомы объяснение значения и грамматика показываются отдельно; история выражения появляется лишь при наличии источника.

Предлагаемый предел первого живого разбора — одно предложение до 50 токенов / 500 символов. При превышении предложить сузить фрагмент; не обрезать ввод и не отправлять весь документ молча. В концепте текст до 6000 UTF-16 единиц предназначен для проверки чтения и выделения; это предел макета, а не обещание parser. Переполненный ввод должен иметь видимый статус до подключения настоящего анализа.

### Заметки и наглядный экспорт

В заметке сохранять выбранный фрагмент, точный контекст, ID исходного документа, диапазон UTF-16 `[start, end)`, область разбора (слово / выражение / предложение), объяснение и его происхождение, перевод с указанием контекста, признаки и зависимости, выбранное значение и доступные источники этимологии. Изменение ввода не должно менять ранее сохранённую заметку. Старый результат после редактирования нельзя сохранить как анализ нового текста.

Первый набор форматов: **Markdown** для личных заметок, **JSON** с версией схемы для повторной обработки, **HTML report** для наглядного просмотра и печати. HTML содержит статическое дерево с подписями, таблицу зависимостей и ссылки на источники; работает без сервера и ключей. Для печати раскрываются существенные данные. PDF через браузерную печать и PNG отдельного дерева — последующий этап. Экспортируемый текст экранируется; пользовательский ввод не исполняется как HTML или скрипт.

Частичный результат экспортируется со статусом недоступного слоя. Реконструкции, сокращённые исторические переходы, авторство Wiktionary и применимая лицензия сохраняются. Экспорт не должен выглядеть более достоверным, чем исходный анализ.

### Что проверяет текущий интерактивный концепт

Два варианта рабочего пространства: **Reading** с чтением и раскрываемыми слоями и **Study** с разделением ввода и результата. В обоих доступны Tokyo Night / Light / Graphite, выбор вхождения слова, выделение выражения, сохранение заметок на время сеанса, копирование Markdown / JSON / HTML и предварительный просмотр HTML-отчёта. Три подготовленных предложения проверяют простой синтаксис, present perfect progressive и relative clause; две сверенные семьи — `water` и `mother`.

Новый произвольный текст остаётся выделяемым, но не получает выдуманных переводов, зависимостей и предков. Концепт не использует живой parser или API-переводчик. Заметки макета не переживают перезагрузку; надёжное локальное хранение относится к реализации. В репозиторном web-концепте доступны скачивание Markdown / JSON / HTML и предварительный просмотр HTML. Есть раскрытие ветвей, масштаб/reset, прокрутка графов, синтаксические дуги и базовые анимации. Drag/pinch pan/zoom, интеграция экспорта в Electron/extension, PDF и постоянные заметки пока не реализованы.

## Перевод семантика и синтаксис

| Слой | Что отвечает | Требование первой версии |
|---|---|---|
| Перевод | Как передать предложение на другом языке | Отдельный результат с названием провайдера, ошибкой и доступными альтернативами |
| Семантика | Что означает слово именно здесь | Выбранное значение, краткая глосса, различение омонимов; ручной выбор при неоднозначности |
| Морфология | В какой грамматической форме употреблено слово | Лемма, часть речи, доступные число, лицо, время, наклонение и другие признаки конкретного языка |
| Синтаксис | От какого слова зависит это слово и какую функцию выполняет | Главное слово, тип связи, выделение связи в тексте/схеме |
| Этимология | Откуда исторически пришла форма | Исторические отношения с источниками, родственники и границы достоверности |

Поле, которого движок не определил, показывается как отсутствующее; приложение не заполняет его догадкой. Морфологическая форма и синтаксическая функция не смешиваются: например, словарный POS не заменяет роль слова в предложении.

Предлагаем использовать универсальные метки частей речи и зависимостей внутри данных, а в UI дать английские подписи и подсказки: **Part of speech**, **Lemma**, **Head**, **Relation**, **Features**. Конкретную схему меток согласовать с выбранным parser.

Сгенерированное объяснение, если оно появится, маркируется и хранится отдельно от результатов parser и словаря. Оно не создаёт этимологические связи. Не обещаем понимание сарказма, всех идиом, скрытых намерений или единственный бесспорный разбор любой фразы.

### Сравнение движков до выбора

| Вариант | Что проверяем | Последствия |
|---|---|---|
| Локальный специализированный parser | Качество английских лемм, морфологии и зависимостей; размер модели, память, скорость, лицензия | Подходит для приватного Electron; web и extension потребуют подходящей браузерной модели или другой реализации адаптера |
| Облачный специализированный parser | Те же признаки и зависимости, поддержка языка, лимиты, стоимость, условия обработки текста | Потребуется отправка текста и сетевой адаптер; возможный backend — пересмотр ADR-009 |
| Облачная языковая модель | Структурированный вывод, правильность связей, повторяемость, ошибки на неоднозначных фразах | Удобное объяснение не доказывает точность грамматики; ключи и расходы защищаются на сервере |

Сравнить два реализуемых кандидата на одном наборе 20 английских предложений: простые, вопросы, отрицания, сложные времена, придаточные, неоднозначность, повтор слова с разной ролью, апострофы и пунктуация. Фиксировать версии моделей, качество каждого слоя, холодный запуск, повторный запуск, память, задержку и стоимость. Выбрать вариант по полезности реальных результатов и ограничениям автора; не назначать заранее неподтверждённую точность «95%».

До выбора облака остаются открыты бюджет и допустимость отправки текста. Сравнение вариантов не разрешает отправлять личные предложения внешнему сервису. Для технического сравнения использовать подготовленные неперсональные примеры, соблюдая явный режим запуска.

## Красивое 2D дерево

### Содержание веток

Исторические предки и потомки образуют основной рисунок. Родственные слова в других языках раскрываются через подтверждённого общего предка. Слова с похожим написанием, звучанием или значением показываются в отдельной группе **Similar words** с пояснением вида сходства. Они не подключаются к историческому стволу без источника о родстве.

Перевод находится рядом с выбранным значением. При сравнении двух переводных эквивалентов приложение отдельно проверяет историческую связь. Совпадающее значение не создаёт общего предка.

Доступные отношения: наследование, заимствование, словообразование, компонент сложного слова, родство без полного пути и неклассифицированная связь. Достоверность утверждения хранится отдельно от типа отношения. Знак `*` означает реконструированную форму, а не автоматически сомнительное родство.

Корень — самый древний доступный подтверждённый этимон. Не каждое слово обязано вести к праиндоевропейскому языку. Отсутствующий промежуток обозначается разрывом или пояснением, а не выдуманными формами.

### Композиция и взаимодействие

- Корень внизу, современные формы вверху. Подпись направления истории; вертикальный шаг означает порядок этапов, а не точную шкалу лет.
- Плавный ствол и непрерывные сужающиеся кривые, мягкая асимметрия и округлая крона. Геометрия воспроизводима при одинаковом графе.
- В начале видна главная линия и ориентировочно 3–6 родственников, если они подтверждены. Это ограничение обзора, а не требование найти шесть для каждого слова.
- Остальные формы свёрнуты. Надпись **Show N more** используется только при известном числе; иначе **Load relatives**.
- Выбор узла подсвечивает путь и открывает карточку формы, языка, значения, отношения и источника.
- Доступны pan/zoom, **Fit tree**, **Focus selected**, сворачивание ветвей и текстовое представление истории.
- Подписи не уменьшаются до нечитаемого размера ради помещения всей кроны. При большом дереве часть подписей скрывается до приближения/выбора, а карточка остаётся читаемой.
- Декоративная листва не имеет смысловых подписей и интерактивных точек. Её отключение не меняет данные.

Новое направление владельца — минимализм Zen Notes/Monkeytype с выбираемыми темами. Первый прототип — Tokyo Night, дополнительная светлая тема и нейтральная тёмная. Палитра выбирается через токены; роли «выбранное слово», «общий предок», «заимствование» сохраняются во всех темах, но конкретные цвета меняются. Тип связи выражается также линией и текстом. Реконструкции — курсив со звёздочкой, диакритика и индексы не обрезаются. Atlas из прежнего ADR-008 остаётся возможной темой, а не обязательным стилем всего приложения. Перед реализацией оформить новое ADR с уточнением старого решения.

Параметры рабочего рендера: межуровневый шаг 100–140 CSS px, зазор подписей от 16 px, читаемые карточки/подписи около 14–16 CSS px в рабочем масштабе. Компактный концепт проверяет композицию; параметры рабочего масштаба уточняются на контрольных деревьях.

### Плавные анимации — отдельный этап

Требование владельца: плавные выразительные анимации выбора, переходов между слоями и раскрытия дерева. На первом концепте достаточно спокойной обратной связи; полировку делать после согласования чтения, плотности и модели данных.

При раскрытии ветви узлы с теми же ID плавно перемещаются, существующие связи перестраиваются непрерывно; контекст выбранного слова остаётся на месте. Подсветка пути и смена карточки занимают ориентировочно 160–280 ms, перестройка ветви 300–500 ms. При сложном каскаде общая длительность до 1200 ms; пользователь может сразу выбрать другой узел, предыдущая анимация прерывается корректно. Это ориентиры, а не обязательная задержка каждой операции.

Без бесконечно качающихся веток, печати объяснений по букве и ожидания завершения декора перед кликом. Уважать `prefers-reduced-motion`: сразу показывать конечную геометрию и сохранять понятное выделение. Тестировать отсутствие наложений подписей во время переходов, стабильность фокуса и отзывчивость на согласованном Mac. Не маскировать анимацией сетевую загрузку или отсутствующий разбор.

## Архитектура и данные

Создать отдельный контракт `SentenceAnalysis`, не превращая словарный `WordAnalysis` в синтаксический результат. Минимальные поля: исходный текст, язык, предложения, все токены с диапазонами, леммы, POS, морфологические признаки, head/deprel, версия движка, статусы и предупреждения. Диапазоны должны однозначно соответствовать JS-строке, включая Unicode; соглашение об индексах документируется. Повторяющиеся слова имеют разные ID, словарные запросы можно дедуплицировать отдельно.

Этимологию хранить графом `nodes + edges`. Узел имеет стабильный ID, язык, форму, словарную статью/этимологический раздел, статус реконструкции и доступные значения. Ребро имеет тип исторического отношения, источник и статус достоверности. Омонимы разных происхождений не сливаются только по написанию.

Дерево — проекция графа для выбранного слова. Несколько родителей и сложные слова не превращаются молча в одну историческую цепочку: дополнительные связи раскрываются отдельно. Исторические данные, переводные отношения, семантическое сходство и синтаксические зависимости — отдельные наборы связей.

Сохранить браузеросовместимое ядро. Локальный parser, если ему нужен процесс или нативная модель, подключается через Electron-адаптер, а не импортируется в `src/core/`. Для web/extension способность анализировать предложение явно обозначается, если такой движок недоступен.

Графика остаётся `d3-hierarchy + React SVG + motion`. В документах упомянуты d3-zoom/modern-screenshot, но их наличие в установленном стеке надо проверять перед использованием. Нет причины менять весь графический движок ради новой кроны.

На первом этапе подготовить три сверенных этимологических графа, затем набор 12 слов с разными случаями. Прототип визуально может использовать тестовую структуру, но вымышленный граф не публикуется как реальная этимология. Живые боковые ветви подключать по одному проверенному формату Wiktionary с пакетными запросами, ограничением глубины, кэшем и обработкой 429.

## Состояния приватность и хранение

Различать загрузку, частичный результат, неподдержанный язык/формат, отсутствие статьи, недостаток данных, сетевую ошибку и ошибку движка. Формулировка **No shared ancestor found in available data** не означает доказанное отсутствие родства. Повтор запроса не удаляет уже доступный результат.

Устаревший ответ предыдущего предложения не заменяет текущий анализ. Пустой ввод не создаёт запросы. Установить явные таймауты; сбой одного слоя не блокирует остальные.

Коллекции остаются локальными, без аккаунта и телеметрии. Для первого релиза не сохранять введённые предложения автоматически; сохранение примера — явное действие, удаление доступно. Словарные и переводческие сетевые запросы объясняются пользователю; локальная коллекция не означает полностью офлайн-приложение.

Каждое историческое утверждение доступно через источник; экспорт содержит атрибуцию Wiktionary и применимую CC BY-SA. Не скрейпить Etymonline. API-ключи не попадают в web/extension bundle, localStorage или синхронизируемый публичный файл. Новый host требует обновления CSP/manifest. Облачная грамматика или backend меняют текущие ограничения приватности и ADR-009: это отдельное решение после сравнения вариантов.

## План реализации небольшими задачами

Для текущего концепта сначала сделать минималистичный интерактивный прототип с темами и проверенными демонстрационными разборами. Демо-данные явно обозначены. Затем подключать доступные бесплатные источники и исследовать локальный parser. Отсутствующий живой синтаксис не выдавать за реализованный. Платный облачный benchmark и backend не являются условиями показа концепта; их сравнение пока может быть документальным.

| Этап | Результат | Условие перехода |
|---|---|---|
| 0. Зафиксировать базу | Актуальная TypeScript-копия, согласованные docs/тесты, личные сценарии | Известно, от какого коммита работаем; английский язык пилота подтверждён |
| 1. Сравнить грамматику | 20 примеров, два кандидата, таблица качества/скорости/размера/стоимости | Выбран engine и согласованы отправка текста/бюджет при необходимости |
| 2. Прототип предложения | UI на проверенных данных: токены, связи, признаки, выбор слова | Автор может разобрать свою фразу и понимает отображаемые связи |
| 3. Выбрать 2D композицию | Три версии на простом, богатом и неполном графах | Выбраны силуэт, плотность, подписи и поведение раскрытия |
| 4. Подключить данные | Новый контракт, адаптер engine, граф происхождения со стабильными ID и источниками | Проверки достоверности и состояний проходят |
| 5. Довести целый сценарий | Предложение → грамматика → лемма/значение → дерево → сохранение/экспорт | Приёмка и три сборки проходят; готов личный ежедневный инструмент |
| 6. Пилот | 8–12 добровольцев на 10–14 дней | Есть конкретные результаты и следующий приоритет |

Этапы 1–3 дают ранние проверяемые решения. Не строить сразу полный многоязычный parser, глобальную сеть Wiktionary, синхронизацию, ежедневную игру и все магазины расширений. Оценку календаря дать после выбора движка и первой вертикальной реализации; сейчас точный срок был бы гаданием.

Для задачи агенту давать один результат, примеры входа/выхода, ограничения и критерий готовности. Например: «Сохрани повторяющиеся токены и диапазоны; предложение `I know that you know.` должно иметь два отдельных `know`; этимологический поиск дедуплицируй отдельно». Это проще проверить, чем поручение «сделай всю лингвистику».

## Первые реальные пользователи

Сейчас достаточно личного использования и бесплатного веб-демо. Electron можно запускать локально для разработки, а его публичный выпуск, подпись, магазины и мобильное приложение отложены. План внешнего пилота ниже применяется после того, как автору понравится концепт. Веб-версия не должна обещать отсутствующую грамматику.

После личной проверки пригласить 8–12 добровольцев с похожими интересами. Дать три задания: разобрать пример, объяснить выбранную зависимость, открыть происхождение собственного слова. Повторное использование проверить через добровольный опрос через неделю. Не добавлять телеметрию ради измерений.

Предложенные пороги для группы из десяти: восемь получают результат без помощи; семь правильно читают одну грамматическую связь и направление этимологической истории; шесть описывают полезное открытие на своём тексте; четверо сообщают о самостоятельном возврате. Самоотчёт не является точной D7-аналитикой, маленький пилот не доказывает массовый спрос.

До широкого запуска: рабочая ссылка/конкретный desktop release, три проверенных примера, скриншот фактического UI, краткая инструкция, форма добровольного отзыва и понятное удаление локальных данных. Неподписанный Electron создаёт трение установки; не делать обход системной защиты обязательным первым шагом для всей аудитории.

Затем один тематический канал с полезным проверенным примером и просьбой о конкретной обратной связи. Массовый SEO, Product Hunt, ежедневный контент и платные сертификаты обсуждать после результата пилота. Публикации и сообщения людям не входят в создание этого ТЗ.
